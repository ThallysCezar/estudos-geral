Ambiente e projeto

Antes de escrever código: onde o Python mora, onde ficam as dependências e como o projeto se descreve.

Ambiente, dependências e pyproject.toml

essencial

Direto: O pyproject.toml é o pom.xml do Python: descreve o projeto e as dependências. Cada projeto tem o próprio ambiente virtual (.venv), uma pasta com o interpretador e as bibliotecas só daquele projeto. Ferramentas como o uv criam o ambiente, instalam as dependências e travam as versões num arquivo de lock.

o caso

Você instala o FastAPI com pip install fastapi direto no Python do sistema. Um mês depois, outro projeto precisa de uma versão diferente da mesma biblioteca, e atualizar uma quebra a outra. No Java isso não acontece porque o Maven resolve as dependências por projeto no ~/.m2 e monta o classpath de cada build. No Python, sem um ambiente virtual por projeto, todos os projetos dividem a mesma pasta de bibliotecas.

≈

Analogia. É como ter uma caixa de ferramentas por obra em vez de uma única caixa para todas. Cada obra leva só o que precisa, na versão que precisa, e o que acontece numa não estraga a outra.

Como surgiu

O Python instalava pacotes num lugar global do sistema. Isso funcionava com um projeto por máquina e virou problema quando vários projetos com versões diferentes passaram a conviver.

Veio substituir: o pip install no Python do sistema e o requirements.txt sem versão travada, que davam builds diferentes em máquinas diferentes.

O mecanismo

O ambiente virtual é uma pasta (.venv) com um link para o interpretador e um diretório site-packages próprio. Ativar o ambiente só coloca essa pasta na frente do PATH; o python e o pip passam a apontar para ela.

O pyproject.toml declara as dependências com faixas de versão; o arquivo de lock (por exemplo, uv.lock) grava as versões exatas que foram resolvidas. É o mesmo papel das versões fixas no pom.xml com o dependencyManagement.

Para que serve

Ter builds reproduzíveis: qualquer pessoa (ou o CI, ou o Docker) recria o mesmo ambiente com um comando, sem depender do que está instalado na máquina.

Por que é importante

Quase todo "na minha máquina funciona" em Python vem daqui. É a primeira coisa que uma vaga de AI Engineer espera que você saiba fazer sem pensar, e a base de qualquer imagem Docker de projeto Python.

a ponte com o Javapom.xml ↔ pyproject.toml; mvn install ↔ uv sync; ~/.m2 ↔ .venv/ (só que por projeto); mvn exec:java ↔ uv run.

Como usar.

uv init meu-chat          # cria pyproject.toml
cd meu-chat
uv add fastapi uvicorn    # adiciona e trava no uv.lock
uv add --dev pytest       # dependência só de desenvolvimento
uv run uvicorn main:app --reload
Para ir alémpip, venv e Poetry: as outras formas

Sem o uv, o caminho padrão da própria linguagem é python -m venv .venv, ativar o ambiente e usar pip install. O Poetry é outra ferramenta popular que também usa o pyproject.toml e um lock. Em projetos antigos você vai encontrar requirements.txt: é só uma lista de pacotes, sem a descrição do projeto.

Ferramentas mudam rápido; confira na documentação qual é a recomendada hoje.
armadilhas
  • Esquecer de ativar o ambiente e instalar no Python do sistema. Com uv run isso não acontece.
  • Commitar a pasta .venv. Ela vai no .gitignore; o que se commita é o pyproject.toml e o lock.
  • Não commitar o lock. Sem ele, o build de amanhã pode trazer versões diferentes das de hoje.

Modelando dados

Onde o Java usa POJO, record e DTO com Bean Validation, o Python tem classe comum, dataclass e Pydantic.

Classes, dataclass e duck typing

essencial

Direto: Classe em Python não declara campos nem tipos obrigatórios: os atributos nascem no __init__. O @dataclass gera construtor, __eq__ e __repr__ a partir de campos anotados, como um record. Não há interface: se o objeto tem o método que você chama, funciona (duck typing); para declarar o contrato, existe o Protocol.

o caso

Você porta um DTO Pedido do Java e escreve uma classe com __init__, getters e setters. Fica com o dobro de linhas e ninguém no time usa getter em Python. Pior: você escreve preco: int, alguém passa "10" e nada reclama, porque a anotação de tipo não é verificada em tempo de execução.

≈

Analogia. Duck typing é contratar pelo que a pessoa sabe fazer, não pelo diploma. Se ela sabe dirigir, serve para motorista; o Java pediria a carteira (a interface) antes de deixar sentar no banco.

Como surgiu

O Python nasceu dinâmico e pequeno, sem cerimônia de tipos. As anotações de tipo vieram depois, opcionais, e o @dataclass entrou para acabar com o código repetitivo das classes de dados.

Veio substituir: as classes escritas à mão, com __init__, __eq__ e __repr__ repetidos em cada uma, e os dicionários soltos usados como objeto.

O mecanismo

Tudo é objeto e os atributos ficam num dicionário da instância; por isso dá para criar um atributo em qualquer momento. O @dataclass lê as anotações da classe e gera os métodos na hora em que a classe é definida. Com frozen=True, a instância fica imutável, como um record.

As anotações de tipo são só metadados: o interpretador não as confere. Quem confere é uma ferramenta estática (mypy, pyright) ou uma biblioteca em tempo de execução, como o Pydantic.

Para que serve

Modelar os dados do domínio com pouco código e escolher o nível de garantia: dataclass para dados internos, Pydantic quando os dados vêm de fora e precisam ser validados.

Por que é importante

Todo o ecossistema de IA em Python (FastAPI, LangChain, SDKs dos provedores) é construído em cima de modelos Pydantic e dataclasses. Entender a diferença entre anotar e validar evita a maior parte dos bugs de quem vem do Java.

a ponte com o JavaPOJO ↔ classe comum; record ↔ @dataclass(frozen=True); interface ↔ Protocol; Bean Validation ↔ Pydantic; Lombok ↔ não precisa.

Como usar.

from dataclasses import dataclass
from typing import Protocol

@dataclass(frozen=True)
class Pedido:              # ~ record Pedido(String id, int total)
    id: str
    total: int

class Notificador(Protocol):   # ~ interface
    def enviar(self, msg: str) -> None: ...

def avisar(n: Notificador, p: Pedido) -> None:
    n.enviar(f"pedido {p.id}: {p.total}")
Para ir alémPydantic: quando o tipo precisa ser verdade

Troque @dataclass por class Pedido(BaseModel) do Pydantic e o tipo passa a ser conferido na criação: "10" vira 10 e "abc" gera um erro claro. É o equivalente a um DTO com Bean Validation, e é o que o FastAPI usa para ler o corpo dos pedidos.

armadilhas
  • Achar que a anotação valida. total: int aceita uma string em tempo de execução; só o Pydantic ou o mypy pegam.
  • Valor padrão mutável. Em dataclass, itens: list = [] é proibido; use field(default_factory=list).
  • Escrever getters e setters. Em Python se acessa o atributo direto; se precisar de lógica, use @property depois.

Qual a diferença entre @dataclass e um modelo Pydantic?
O dataclass só gera os métodos (construtor, igualdade, repr) e não confere os tipos. O Pydantic confere e converte os tipos na criação e devolve um erro claro quando o valor é inválido. Dataclass para dados internos; Pydantic para dados que vêm de fora.← Toque para voltar à pergunta

API com FastAPI

O Spring MVC do Python: rotas, validação, injeção de dependência e documentação, com bem menos configuração.

FastAPI: rotas, validação e injeção de dependência

essencial

Direto: FastAPI é um framework web em que a rota é uma função com decorator (@app.get), os parâmetros e o corpo são lidos e validados pelos tipos (com Pydantic) e as dependências são injetadas com Depends(). A documentação OpenAPI sai pronta em /docs.

o caso

Você precisa expor um modelo de IA numa API. No Spring seriam um controller, um DTO com Bean Validation, um service com @Autowired e o springdoc para a documentação. No FastAPI, uma função de dez linhas faz o mesmo: lê o corpo, valida, recebe o serviço injetado e aparece documentada. É por isso que as vagas de IA pedem FastAPI.

≈

Analogia. É o Spring Boot com as anotações viradas em tipos: em vez de dizer ao framework o que cada parâmetro é com @RequestBody e @PathVariable, você declara o tipo e ele deduz o resto.

Como surgiu

Os frameworks web do Python (Flask, Django) são anteriores às anotações de tipo e ao async. O FastAPI foi feito em cima dos dois: usa os tipos para validar e documentar e roda sobre o ASGI, que suporta async.

Veio substituir: o Flask com validação escrita à mão e documentação separada, que era o caminho comum para APIs pequenas em Python.

O mecanismo

Ao subir, o FastAPI lê a assinatura de cada função de rota. O que está no caminho vira parâmetro de path, tipos simples viram query string e modelos Pydantic viram o corpo. Com isso ele monta a validação e o schema OpenAPI.

Depends(funcao) diz ao framework para chamar aquela função a cada pedido e passar o resultado; dá para encadear dependências e trocar por uma falsa nos testes com app.dependency_overrides. O servidor que roda a aplicação é o uvicorn, como o Tomcat embutido do Spring Boot.

Para que serve

Publicar serviços HTTP em Python com validação e documentação automáticas, que é a forma padrão de servir modelos e agentes de IA.

Por que é importante

Aparece em boa parte das vagas de AI Engineer e é a porta de entrada do Projeto 1 da trilha de IA. Para quem vem do Spring, é o ponto em que você fica produtivo em Python mais rápido.

a ponte com o Java@RestController + @PostMapping ↔ @app.post; DTO + @Valid ↔ modelo Pydantic; @Autowired ↔ Depends(); springdoc ↔ /docs; Tomcat ↔ uvicorn.

Como usar.

from fastapi import FastAPI, Depends
from pydantic import BaseModel

app = FastAPI()

class Pergunta(BaseModel):
    texto: str

def get_llm() -> "ProvedorLLM":     # ~ um @Bean
    return ProvedorReal()

@app.post("/chat")
def chat(p: Pergunta, llm=Depends(get_llm)):
    return {"resposta": llm.responder(p.texto)}
Para ir alémdef ou async def?

Rotas com def rodam num pool de threads; com async def, rodam no loop de eventos e precisam usar bibliotecas assíncronas (por exemplo, o cliente HTTP assíncrono do provedor). Chamar uma função bloqueante dentro de async def trava o servidor inteiro. Na dúvida, comece com def.

Confira na documentação do FastAPI a seção sobre concorrência e async.
armadilhas
  • Chamada bloqueante dentro de async def trava todos os pedidos ao mesmo tempo.
  • Criar o cliente do LLM a cada pedido dentro da rota; crie uma vez e injete com Depends.
  • Devolver o modelo interno com campos que não deviam sair; use response_model para controlar a resposta.

Como aprender de verdade: vídeos, pesquisa e prática

Para quem já programa, Python se aprende portando código, não fazendo exercício de iniciante.

O ciclo, as fontes e como praticar

método

Direto: Você já sabe programar; o que falta é o jeito Python de fazer as mesmas coisas. O ciclo que fixa é ler o tópico, ver um vídeo que dê o mapa, conferir na documentação oficial e portar um pedaço de código seu do Java. Vídeo dá o mapa, documentação dá a precisão, o porte fixa.

o caso

Você termina um curso de Python para iniciantes, sabe fazer laços e funções, e trava ao abrir um projeto FastAPI real: ambiente virtual, Pydantic, Depends, async. O curso ensinou a linguagem para quem não programa. Quem vem do Java precisa do contrário: pular o básico e ir direto às diferenças.

Canais e cursos em português.

  • FastAPI do Zero, de Eduardo Mendes (dunossauro): curso gratuito, em texto e vídeo, que monta uma API completa com FastAPI, SQLAlchemy, testes e deploy. É o mais próximo do Projeto 1.
  • Live de Python, também do Eduardo Mendes: lives semanais no YouTube sobre um tema por vez (tipagem, dataclasses, Pydantic, async, pytest). Bom para os tópicos isolados.
  • Curso em Vídeo, de Gustavo Guanabara: curso de Python do começo. Use só para consultar a sintaxe; para quem já programa, é lento.
  • Documentação oficial em português: o tutorial do Python (docs.python.org/pt-br) e a documentação do FastAPI, que tem tradução para o português.

Confira se o conteúdo está atualizado antes de seguir um curso inteiro; ferramentas como o uv são recentes e cursos antigos usam pip e venv.

Como pesquisar. Pesquise pela ponte com o Java: "python equivalente a interface java", "pydantic vs dataclass", "fastapi depends vs spring autowired", "pytest fixture vs junit beforeeach". Confira sempre na documentação oficial do Python, do Pydantic e do FastAPI, porque respostas antigas mostram jeitos que já mudaram.

Mini-projeto na sua stack. Pegue um endpoint de um projeto Spring seu (um CRUD simples serve) e porte para FastAPI:
1. Mesmo contrato: mesmas rotas, mesmos campos e mesmos códigos de erro.
2. Mesma validação: o que era Bean Validation vira Pydantic.
3. Mesmos testes: o que era JUnit e MockMvc vira pytest e o TestClient do FastAPI.
4. Compare num README: linhas de código, tempo de subida e o que foi mais fácil ou mais difícil em cada lado.
